# 预留接口登记表

> 制度来源：ADR-0001 §7。`habits`/`shared_secrets`/`user_notes` 三个死字段的教训——没有登记制度的预留必然烂掉。
> 规则：**任何预留接口/字段/待观察参数必须在此登记**；代码处用 `# RESERVED(Rn)`（未实现预留）或 `# OBSERVE(Rn)`（已实现待观察）注释锚定；调用或删除前先查本表；每批收尾更新状态列。
> ❗ **锚点类型怎么判**：看**锚点描述的对象**是否已实现，不看整行。`RESERVED(Rn)` 用于对象**本身未实现**——含「已实现埋点 + 未实现消费方」的预留（R1 二期提炼未做、R8 闸门判据未实现）与协议位（R13）；`OBSERVE(Rn)` 用于对象**已实现**。**每批收尾必须同时核对两件事**：① 有无锚点；② 锚点类型是否与实现状态一致。2026-09-29 实证：前次核对只查了①，漏了② → R6×2 / R9×3 / R18×1 挂错（对象早已实现却标 RESERVED），R10 废弃号残留锚点。
> ❗ **已废弃条目已迁出**（2026-09-29 整理）：R3 / R10 / R19 / R32 / P18 及「已处决项」「跨插件契约字段」两段整体迁至《**废弃接口登记表.md**》，号码作废不复用；决策留痕段的历史引用保留原样。
> 📁 **2026-09-29 拆分**：调参观察点（P 项）→《**调参观察点表.md**》；外部版本约束（升级硬约束）→《**外部版本约束.md**》；已废弃条目 →《**废弃接口登记表.md**》。历次「本轮决策留痕」段落已删除（各批裁决均在 `.workbuddy/memory/` 当日工作日志留档）；锚点核对历史保留 2026-09-29 复核痕迹（见文末）。
