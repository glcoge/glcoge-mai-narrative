# ADR-0005：验收回路——本地 Docker + 仿真适配器 + 回放台

- 状态：已接受（2026-09-24）
- 背景：服务器已到期下线；用户本机可装 Docker 完整复刻运行环境，持有 bot QQ 凭证（新设备风控有解法）；NapCat 适配器支持用户白名单/黑名单，真实好友回复边界完全可控
- 版本真值：归档 compose 用 `sengokucola/maibot:latest` 镜像——**本地拉镜像即运行时真值**，一次性解决 R1（归档 src/ 1.2.0 是旧 checkout）并验证 `model_name` 路由可用性

## 决策

1. **三轨验收设施**：
   - **仿真适配器（日常，B 轨）**：不连 QQ，脚本按 NapCat WS 协议注入消息帧——封闭、可自动化、零风控；用 `E:\Downloads\MaiBot-export\messages.jsonl` 的真实消息序列（1152 条 / 11 私聊会话 / 08-30~09-22，字段含 session_id/sender_id/is_bot/is_command/segments）做回放用例
   - **本地 Docker 全栈（里程碑）**：`sengokucola/maibot:latest` + 挂载归档配置（脱敏后）+ 真实插件，端到端实测
   - **真凭证人工审（批收尾）**：NapCat 白名单只留用户自己的号（`mode_user_ids` 现成机制），每批收尾人工过一眼
2. **回放台**（`tools/replay/`，进 git，正式验收工具非临时脚本）：
   - 一期数据 = 归档插件侧（chronicle/events/snapshots/metrics，`E:\Downloads\MaiBot`）+ **MaiBot-export 聊天记录**（用户已解析整理完毕，直接喂）
   - 用途：批 1 泄露用例回归、批 2 晋升机空转验证（喂 26 天数据看产出节奏）、批 4 晋升数值定标、指标 4 基线测定
   - 数据路径走 CLI 参数，不硬编码、不把归档数据复制进仓库
3. **指标 4（state_diversity）双轨埋点**：
   - A 轨（注入侧，便宜先埋）：每日快照中实际进 prompt 的状态组合 distinct 熵
   - B 轨（产出侧，**闸门判据挂这条**）：主动消息/生活片段文本间多样性（embedding 或字符 n-gram，选型批 1 定，登记表 R7）
   - 理由：注入状态换着花样变但输出一模一样，就是"只长数字不长故事"的翻版；产出侧才是用户可感多样性。用户可随时人工拉聊天记录核验
4. **数据回路小修（批 1）**：
   - `is_command` 在 `chat.receive.after_process` 恒 False（宿主在命令链后才置位，`bot.py:294/:595`）→ 插件侧本地正则判定命令文本，不进素材、不刷关系值（登记表 R9：宿主修复后可删）
   - **tier 语义重定义**：从"资格门"改回"详略档"——所有生活片段都可当由头，tier 只决定注入展开详略；由头取材优先"未用过且与最近对话不撞车"（轻量文本重叠判定）。根治 26 天 100% minor → 由头通道空转
5. **铺群闸门判据改挂指标 4 B 轨**，基线值由批 1 回放数据测定（登记表 R8）。
