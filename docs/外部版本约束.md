# 外部版本约束

> 2026-09-27 新增（部署期硬约束）；2026-09-29 从《预留接口登记表.md》拆出独立成档。
> 本表不属于「预留接口」，但**每次升级宿主都必须先看这里**。
> 登记理由是 2026-09-26 深夜踩到的坑：宿主升到 1.3.0 后，NapCat adapter **v1.4.0 因 manifest 声明 `host max = 1.2.99` 被拒绝加载**
> → 后果是**整个 MaiBot 收发不了 QQ 消息**，而插件本身一切正常、日志里只能看到一行「Manifest 校验失败」。

| 组件 | 要求 | 依据 / 后果 |
|---|---|---|
| 宿主 MaiBot ↔ NapCat adapter | adapter **必须 ≥ v1.5.0**（1.4.0 只到 host 1.2.99） | v1.5.0 manifest 声明 host `1.3.0~999.99.99`。⚠️ **v1.5.0 只有 git tag、没发 GitHub release** —— `gh release list` 看不到，必须用 `git ls-remote --tags` 才能发现；升级方式是下载 tarball 解压后覆盖插件目录（`config.toml` 不在仓库内，故本地配置不会丢） |
| 逃生开关 | `[debug].force_plugin_compatibility = true`（需重启） | 官方 1.3.0 新增的绕过校验开关。**属 hack**：发现存在新版 adapter 时优先升 adapter，别长期依赖此开关 |
| 本插件 Manifest 区间 | host `1.0.0~1.99.99` / sdk `2.7.0~2.99.99` | 已覆盖宿主 1.3.0 / SDK 2.8.2，**无需改动** |
| 备份目录位置 | ❗ **绝不能放在 `plugins/` 目录下** | host 扫描 plugins 全目录；同 plugin id 的旧 manifest 会被一起扫到并**胜出**（表现为「明明换了新版，日志仍报旧版」）。备份请放 `data/plugin-backup/` |
| 归档数据真源（回放台用） | `E:\Downloads\narrative\narrative.db` + `metrics\`，配 `E:\Downloads\MaiBot-export\messages.jsonl` | ⚠️ db/metrics **不在** `MaiBot-export\` 下（该目录只有 messages/csv/md）。用错路径会静默退化成 6/8 |
